# #54015 [Kimi-K3] Merge MLA gate into QKV-A projection

https://github.com/vllm-project/vllm/pull/54015 · gau-nernst · MERGED · created 2026-08-27T07:44:15Z · merged 2026-08-28T00:47:19Z

## Purpose

This PR merges MLA's `g_proj` (used for output gating) into QKV_a projection to create a larger GEMM. We don't expect this to have a large impact as the original QKV_a gemm is already quite large. The main purpose of this PR is to prepare for the upcoming fused AG-GEMM (used in SP), which benefits significantly from having a larger GEMM.

What makes this PR a bit more complicated is that currently we have a low-latency optimization for MLA: `g_proj` runs in a side stream when bs<512, so that `g_proj` can overlap with `qkv_a_proj`+MLA. From my testing, this side-stream optimization is faster than running a combined `qkv_a_g_proj` GEMM at bs=1, hence we should still keep this optimization.

To do so, this PR does **weight slicing** when `bs<512` to run `g_proj` in side stream, preserving the current behavior. When `bs>=512`, the merged GEMM replaces the sequential GEMM baseline.

Dispatch logic

- Entrypoint: `forward()`
  - Q full rank (Kimi-Linear): `_forward_full_rank_q`. This is unchanged, because Kimi-Linear doesn't use output gate
  - Q low-rank (Kimi-K3): `_forward_q_lora`
    - When running g_proj in side stream is eligible (M<512, BF16 weights): slice weight and run (qkv_a+MLA) || (g)
    - Otherwise, run qkv_a_g together

Limitations:

- Since we do weight slicing here, we must handle each quantization explicitly (i.e. for quantized weights, need to slice the scale factors as well. Also need to manually dispatch the GEMM function, can't rely on Linear module).
- This PR currently only supports BF16 weight slicing (official Kimi-K3 weights). In other words, if QKV_a and g_proj are **not BF16, running `g_proj` in side stream is disabled**. This may LL perf of 3rd party quantizations, such as `nvidia/Kimi-K3-NVFP4`. We can expand support as needed cc @wzhao18
- `bs<512` threshold might not be optimal. This PR does not re-tune this threshold.
