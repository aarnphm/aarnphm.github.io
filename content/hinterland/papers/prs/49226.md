# #49226 [Bugfix][KVConnector] Disable cross-layer KV blocks for per-token-head quant

https://github.com/vllm-project/vllm/pull/49226 · Achyuthan-S · MERGED · created 2026-07-20T16:42:10Z · merged 2026-07-26T02:24:28Z

## Purpose

Fixes #48412.

Combining `OffloadingConnector` with a per-token-head quantized KV cache
(`fp8_per_token_head` / `int8_per_token_head` / `int4_per_token_head`) corrupts
generations on the **first forward pass**, before any offloaded block is ever
restored.

### Root cause

`OffloadingConnector.prefer_cross_layer_blocks` is hardcoded `True`. For
single-group models on backends with `indexes_kv_by_block_stride` (e.g.
`TRITON_ATTN`), the model runner therefore allocates a **cross-layer** KV cache
(`allocate_uniform_kv_caches` in `kv_connector_model_runner_mixin.py`): one
contiguous buffer shared by all layers.

Per-token-head quant stores an inline fp32 scale in a padded tail of each
`(head, token)` cell. The attention backend carves strided fp32 views over
those pad bytes in `_ensure_scale_caches` (`triton_attn.py`), assuming a
**per-layer, contiguous** buffer. Against the interleaved cross-layer
allocation, the assumed block stride is wrong and every layer's scale views
collide at the same offset, so writing scales aliases neighboring K/V data and
corrupts the cache from the first decode.

### Fix

Return `prefer_cross_layer_blocks = False` when the KV cache dtype uses
per-token-head scales, so these models take the **per-layer** offload path
(which lays out each cell's scale pad correctly). Non-per-token-head configs —
plain `fp8` included — are unchanged and still prefer the cross-layer layout.

This is a soft fallback, not a hard failure: offloading still works for these
dtypes via the per-layer path — only the cross-layer transfer optimization is
skipped, and only for per-token-head dtypes. Teaching the cross-layer allocation
and `_ensure_scale_caches` to pack scales in the shared buffer would restore that
optimization, but is a larger, hotter-path change and can be a follow-up.

### Relationship to #48411 (merged)

#48411 fixed the **per-layer** offload _transfer width_ — inline scales were
truncated mid-cell on restore. It explicitly deferred the **cross-layer**
allocation incompatibility to #48412, which this PR addresses. With #48411
already in `main`, this PR completes per-token-head + offloading support:
models fall back to the (now-correct) per-layer path instead of the corrupting
cross-layer allocation. No other open PR addresses #48412.
