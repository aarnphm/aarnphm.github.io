# #54517 [Qwen3.8-Flash-Next] Fuse Qwen4Exp PLE kernels

https://github.com/vllm-project/vllm/pull/54517 · gau-nernst · MERGED · created 2026-08-31T06:34:10Z · merged 2026-09-02T04:32:16Z

## Purpose

- Optimizations:
  - Fuse n-gram ID generation, dilated short-conv, and the PLE gate on NVIDIA
  - Merge key/value projections
- n-gram ID generation still has PyTorch fallback for future PLE offload (#53899, not landed in main)
- Original PyTorch implementations of dilated short-conv (prefill, decode, spec-decode) are moved to `test_ple.py` for correctness testing. Production code only contains Triton kernel now. 

### Correctness details

**n-gram ID generation**
- Preserve PyTorch int64 overflow behavior. Overflow hashes may become negative, so the kernel explicitly normalizes modulo results to match torch.remainder, guaranteeing every ID remains within its head-specific range: [offset, offset + vocab_size).kernel 
- Ragged request boundaries are resolved from query_start_loc, including empty requests and non-power-of-two request counts. Tokens preceding the current chunk come from persistent n-gram context, and crossing EOS replaces all older suffix positions with EOS.

**Dilated short-conv**
- Preserves cache semantics for decode, prefill, and speculative decode. Speculative state is rolled back by num_accepted_tokens - 1, while current candidate inputs are retained for the next target-model step.
- Convolution output and cache writeback use separate kernels so state is not overwritten before all causal reads complete.
- For mixed-spec/non-spec batches, token positions are looked up inside the kernel, eliminating separate gather/scatter ops.

**PLE gate**
- Match PyTorch numerics exactly (cast intermediates to BF16 as appropriately)

## Microbenchmarks

All results are obtained with GB300. Although we only show speedup here, another major benefit is greatly reduced memory usage as we don't materialize temporary intermediates.
